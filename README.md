# goit-algo2-hw-07

## Висновки до задачі 2

У ході роботи було порівняно два підходи до обчислення чисел Фібоначчі: використання `LRU Cache` та `Splay Tree` для збереження вже обчислених значень.

Для значень `n` від 0 до 950 з кроком 50 було проведено вимірювання середнього часу виконання за допомогою модуля `timeit`. Результати були представлені у вигляді таблиці та графіка.

За отриманими результатами `LRU Cache` показав кращу продуктивність у всьому досліджуваному діапазоні. Наприклад, для `n = 950` середній час виконання становить приблизно:

* `LRU Cache` — `0.000188` с;
* `Splay Tree` — `0.000845` с.

Таким чином, для `n = 950` використання `LRU Cache` приблизно у **4,5 раза швидше**, ніж використання `Splay Tree`.

Зі збільшенням `n` різниця між двома підходами загалом збільшується. Це пов'язано з тим, що `LRU Cache` реалізований на рівні Python і забезпечує дуже швидкий доступ до закешованих результатів, тоді як `Splay Tree` потребує виконання операцій пошуку, вставки та сплайювання вузлів.

`LRU Cache` також має перевагу у простоті реалізації: достатньо використати стандартний декоратор `@lru_cache`. У випадку `Splay Tree` необхідно самостійно реалізовувати структуру дерева та операції над нею.

Отже, у межах проведеного експерименту **LRU Cache виявився ефективнішим для обчислення чисел Фібоначчі**, особливо зі збільшенням `n`. `Splay Tree` також дозволяє ефективно зберігати вже обчислені значення, але в даному випадку додаткові операції роботи з деревом роблять його повільнішим за стандартний `LRU Cache`.
